# SendGrid Provider

The SendGrid provider is used to manage [SendGrid](https://sendgrid.com) (a Twilio product) resources: API keys,
subusers and teammates, sender authentication, transactional templates, event webhooks, Marketing Campaigns
lists/segments/custom fields/Single Sends, tracking and mail settings, IP addresses/pools/warmup, and partner
accounts. The provider needs to be configured with an API key before it can be used.

## Getting Started

See the [Authentication guide](guides/authentication.md) for how to configure credentials, including EU data
residency and On-Behalf-Of subuser access. If you're migrating from another SendGrid Terraform provider, see the
[Migration guide](guides/migrating-from-other-providers.md).

## Example Usage

```terraform
terraform {
  required_providers {
    sendgrid = {
      source = "twilio-labs/sendgrid"
    }
  }
}

provider "sendgrid" {
  # api_key can also be set via the SENDGRID_API_KEY environment variable.
  api_key = var.sendgrid_api_key
}

variable "sendgrid_api_key" {
  type      = string
  sensitive = true
}
```

## Schema

### Optional

- `api_key` (String, Sensitive) SendGrid API key. Can also be set via the `SENDGRID_API_KEY` environment variable.
- `host` (String) SendGrid API host. Defaults to `https://api.sendgrid.com`; set to `https://api.eu.sendgrid.com` for EU regional accounts. Can also be set via the `SENDGRID_API_HOST` environment variable.
- `on_behalf_of` (String) Sets the `on-behalf-of` header on every request, causing all requests to act as the given subuser or account (e.g. `account-id <account-id>`). Can also be set via the `SENDGRID_ON_BEHALF_OF` environment variable. Applies to the whole provider; there is currently no per-resource override.
